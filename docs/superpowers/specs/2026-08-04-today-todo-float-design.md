# 今日待办悬浮窗 macOS 小应用设计规格

日期：2026-08-04

## 目标

提供一个轻量、常驻的 macOS 原生小工具：用户可以随手记录当天待办和项目提醒，在桌面保持一个不抢焦点的小型悬浮窗，并在 10:00–19:00 每小时通过 macOS 通知提醒用户查看。

## 范围

包含：

- SwiftUI 界面与 AppKit 窗口控制
- 菜单栏常驻图标
- 约 300×360 pt 的可拖动悬浮窗
- 约 42×42 pt 的收起状态，可点击恢复
- 今日任务的新增、编辑、删除、完成勾选
- 本地持久化，按自然日隔离任务
- 10:00、11:00 … 19:00 的每日通知
- 通知权限申请、权限状态提示和提醒暂停/恢复
- 登录时自动启动

不包含：云同步、账号、多人协作、跨平台版本、复杂项目管理、远程服务。

## 用户体验

### 悬浮窗

窗口默认显示在屏幕右上区域，带圆角和轻微阴影，保持在其他普通窗口之上但不抢焦点。标题区显示“今日待办”和当前日期；主体是任务列表，每行有完成勾选框、文本和删除操作；底部提供“添加任务”和收起按钮。

用户可拖动窗口标题区改变位置。点击收起后，窗口缩为小圆形按钮并保留在原位置；点击圆形按钮恢复完整窗口。收起/展开不触发通知，不切换当前活动应用。

### 菜单栏

菜单栏图标提供：显示/隐藏悬浮窗、添加任务、暂停/恢复今日提醒、打开通知设置提示、退出应用。菜单栏是应用的常驻入口，即使悬浮窗被收起也可用。

### 通知

首次运行请求 macOS 通知权限。每天在本地时间 10:00 到 19:00 的整点各发送一次，共 10 次；文案为“看一下今日待办”，副标题可显示未完成任务数量。通知只出现在通知中心，不自动展开、移动或激活悬浮窗。

若用户拒绝通知权限，应用继续可用，并在菜单栏菜单中显示权限状态和系统设置入口。用户可通过菜单暂停或恢复当天剩余提醒。

## 数据与状态

任务模型至少包含：稳定 ID、文本、完成状态、创建时间、更新时间和所属日期。数据保存在应用支持目录的本地 JSON 或 UserDefaults 中；启动时加载当天任务，跨天后切换到新的空白日期集合，历史数据保留但不在主窗口展示。

提醒状态包含：当天是否暂停、已发送的提醒时间点集合、最后计算时间。调度器依据当前日期和时间计算下一次未发送整点；从睡眠恢复时只补发当前时间之后的下一个有效整点，不追发错过的多个通知。

## 架构

- `AppDelegate`：应用生命周期、菜单栏入口、通知权限初始化。
- `FloatingPanelController`：创建、定位、显示/隐藏和收起状态的 AppKit 面板。
- `TodoStore`：任务读写、按日期切换、增删改和完成状态更新。
- `ReminderScheduler`：计算整点、处理跨天和睡眠恢复、提交本地通知。
- SwiftUI View 层：今日待办列表、编辑行、空状态和操作按钮。

SwiftUI 负责内容和状态，AppKit 负责无边框悬浮面板、窗口层级、拖动和收起动画。各组件通过 `ObservableObject` 或明确的方法边界通信，避免视图直接操作窗口细节。

## 错误处理

- 本地数据读写失败：保留当前内存数据，显示非阻塞错误提示，并记录日志。
- 通知权限不可用：不阻塞任务功能，菜单中提供权限状态和设置入口。
- 无法定位屏幕：回退到主屏幕可见区域内的默认位置。
- 系统时间变化：重新计算下一次提醒，避免重复发送。

## 验证标准

- 新增、编辑、删除、完成任务后，重启应用数据仍保留。
- 收起后的圆形按钮可在原位恢复悬浮窗，窗口不抢当前应用焦点。
- 每个有效整点最多发送一次通知；10:00–19:00 之外不发送。
- 跨天后主窗口显示新日期且为空，历史数据不会丢失。
- 拒绝通知权限时应用仍能正常记录和查看任务。
- 退出并重新打开应用后菜单栏入口和窗口状态可恢复。
